## 这是什么

NapCatQQ 是一个「现代化的基于 NTQQ 的 Bot 协议端实现」，把 QQ 客户端桥接到 OneBot 11 生态。

源站下线后，官方文档无处可查。本仓库把 Wayback Machine 上能抓到的全部页面、样式与图片重新拼装成一套**可直接双击打开**的静态站点，并额外提供一份合并好的 Markdown 文本，方便手机、Kindle 或纯文本环境阅读。

**本仓库不包含 NapCat 的程序本体或二进制文件**，只有文档。

## 使用方法

### 方式一：在线访问（最省事）

仓库启用 GitHub Pages 后，直接打开：

```
https://<你的用户名>.github.io/<仓库名>/
```

`pages.yml` 会在每次 push 到 `main` 时自动构建并部署，无需手动操作。

### 方式二：直接本地打开

下载 Release 里的 `NapCat-Docs-Archive-*-site.zip`，解压后双击 `index.html`。

页面是 VitePress 预渲染的静态 HTML，**正文与样式全部内联在文件里，不需要服务器，也不需要联网**。

> ⚠️ 部分 JS 分块（共 2194 个）未能全部抓取，因此**站内搜索框与主题切换不可用**，侧边栏折叠等交互也受限。正文阅读、目录跳转、代码块、图片均正常。

### 方式三：本地起个服务（体验更接近原站）

```bash
# 在解压目录内
python -m http.server 8080
# 浏览器打开 http://localhost:8080
```

### 方式四：看 Markdown

Release 里的 `NapCat-Docs-Archive-*-markdown.zip`，单文件，纯文本，手机阅读友好。

## 发布流程

仓库配了两条工作流，各管一件事：

| 工作流 | 触发 | 作用 |
| --- | --- | --- |
| `pages.yml` | push 到 `main` | 构建并部署在线文档站 |
| `release.yml` | 打 tag / 手动 | 打包 zip 并发布 Release |

### 一、在线文档站（GitHub Pages）

**首次启用需要手动操作一次：**

1. 进入仓库 **Settings → Pages**
2. **Source** 选 **GitHub Actions**（不要选 Deploy from a branch）
3. 保存

之后每次 push 到 `main`，`pages.yml` 会自动：

1. 校验 `site/index.html`
2. 运行 `tools/relativize.py`，把 `/assets/...` 这类根路径引用改成相对路径
   （子目录部署必须，否则资源全 404）
3. 生成 `.nojekyll`，防止 Jekyll 忽略下划线目录
4. 上传并部署到 Pages

访问地址：`https://<用户名>.github.io/<仓库名>/`

### 二、离线归档发布

打一个 tag 即可自动打包并发 Release：

```bash
git tag v2026.11.14
git push origin v2026.11.14
```

也可以在 **Actions → Release Archive → Run workflow** 里手动触发，可自定义版本号。

工作流会：

1. 校验 `site/index.html` 存在
2. 把 `site/` 压成 `NapCat-Docs-Archive-<版本>-site.zip`（最高压缩）
3. 若有 `NapCat文档归档.md`，另压一份 markdown 包
4. 生成 `SHA256SUMS.txt`
5. 创建 GitHub Release 并上传全部产物，正文自动附带页面统计
